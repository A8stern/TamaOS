# Harness

The root `Makefile` is the stable entry point for humans, agents, and CI. The harness itself is intentionally language-agnostic.

## Commands

```sh
make setup
make check
make test
make build
make ci
```

`make ci` is deterministic and runs locally and in GitHub Actions. Independent agent review remains local:

```sh
make review
make prepush
```

`make setup` configures the tracked `.githooks/pre-push` hook. Before every push, the hook reruns `make ci` and requires three independent PASS reports for the exact `HEAD` commit. The reports must use one affected-language profile and name three distinct actual skill IDs for its correctness, architecture, and verification-risk slots. The architecture report must name the consulted language architect, accepted clearance, and architecture sources it checked. A language without a complete profile cannot pass. Review evidence lives under ignored `.harness-state/reviews/<SHA>/`; it is neither committed nor generated by CI.

The `$tamaos-code-review` coordinator defines the evidence schema and dispatch rules; each language profile supplies the three concrete review skills. Any new commit invalidates previous evidence.

Language profiles are registered explicitly in `harness/review-profiles.json`. The registry is empty until concrete review skills are selected for a language; do not add placeholder IDs.

Hardware actions require an explicit project so they cannot accidentally target every registered device:

```sh
make firmware PROJECT=firmware
make size PROJECT=firmware
make flash PROJECT=firmware
make monitor PROJECT=firmware
```

## Registering a project

Add one tab-separated line to `harness/projects`:

```text
firmware<TAB>apps/firmware
```

The project directory must contain an executable `.harness` script. It receives one action and translates it into the native commands for that project:

```sh
#!/bin/sh
set -eu

case "$1" in
  setup)    rustup show ;;
  check)    cargo fmt --check && cargo clippy --all-targets -- -D warnings ;;
  test)     cargo test ;;
  build|firmware) cargo build --release ;;
  size)     cargo size --release -- -A ;;
  flash)    cargo run --release ;;
  monitor)  espflash monitor ;;
  *)        echo "unsupported action: $1" >&2; exit 2 ;;
esac
```

This snippet is illustrative, not the TamaOS firmware configuration. Pin the actual Rust target and flashing commands after the toolchain spike.

Keep language-specific behavior inside the project adapter. Extract a shared adapter only after two real projects need the same implementation.
